# Task97 ข้อกำหนดและกรณีทดสอบ U8

การให้ แก้ไข และลบคะแนนรีวิวของแนวข้อสอบและสรุป PDF

รุ่น 0.2 วันที่แก้ไข 14 พฤศจิกายน 2569 สถานะผู้ตรวจทบทวนแล้ว รอ PO ยืนยันมติ D01–D04

เอกสารนี้ขยายรายละเอียด Story U8 และ U8-TC01 ถึง U8-TC09 โดยคงรหัสและเกณฑ์เดิม เพื่อให้ทีมตรวจรับระบบรีวิวบนแนวข้อสอบและสรุป PDF ได้ตรงกัน แนวทาง D01–D04 อ้าง Task94 รุ่น 0.2 และแบบ Task102; ยังไม่ถือเป็นมติของ PO

## Story เดิมที่ใช้เป็นเกณฑ์

ในฐานะนักศึกษามหาวิทยาลัยธรรมศาสตร์ที่อ่านแนวข้อสอบหรือสรุปของผู้ใช้อื่นแล้ว ฉันต้องการให้คะแนนความเป็นประโยชน์ด้วยดาว 1–5 พร้อมข้อความประกอบตามต้องการ และกลับมาแก้ไขหรือลบรีวิวของตนเองได้ เพื่อให้นักศึกษาคนอื่นมีคะแนนและความคิดเห็นประกอบการเลือกเนื้อหา โดยความคิดเห็นที่เผยแพร่ยังสะท้อนประสบการณ์ปัจจุบัน

## ขอบเขตของ Task97

ครอบคลุมข้อมูลบังคับและเสริม สิทธิ์ของผู้เขียนรีวิว ผลสำเร็จและผิดพลาด ข้อมูลทดสอบ ผลคาดหวัง และคำถามสำหรับ PO ทุกกรณีที่เกี่ยวข้องต้องทดสอบกับ guide และ summary แยกกัน ไม่เปลี่ยน Story ให้รองรับเฉพาะพฤติกรรมที่โค้ดเดิมมีอยู่

แบบตาราง DAO และ Sequence Diagram อยู่ใน Task102 ส่วนหน้าจอ Storyboard และ UI states อยู่ใน Task107 เอกสารนี้อ้าง API เพื่อระบุผลภายนอก ไม่ออกแบบหรือ implement ส่วนเหล่านั้นซ้ำ

### รายละเอียดที่รับมาตั้งต้นจาก Task94

ข้อเสนอใน contract คือ trim ข้อความ เก็บช่องว่างล้วนเป็น null และจำกัด comment ไม่เกิน 2,000 Unicode code points ไม่รับคะแนนชนิด string boolean หรือทศนิยม PUT แทนที่ rating กับ comment ทั้งชุด จึงต้องส่ง rating ทุกครั้ง ถ้าไม่ส่ง comment จะล้างข้อความเดิม

Task94 เสนอให้ลบรีวิวแล้วสร้างใหม่ได้ ไม่เก็บประวัติการเปิดอ่านเป็นเงื่อนไข Backend และไม่เพิ่มคะแนนเฉลี่ยหรือ moderation ในขอบเขตนี้ เกณฑ์ว่าอ่านผลงานแล้วเป็นบริบทของ Story ยังต้องถาม PO ว่าต้องมีการบังคับเพิ่มเติมหรือไม่

ค่าตั้งต้นและ error code ของ Task94 ยังไม่ใช่มติรับรองจาก PO หากได้ข้อสรุปต่างออกไป ต้องปรับส่วน U8 ของ contract และ fixtures พร้อมให้ Frontend กับ Backend ทบทวน ไม่เปลี่ยนเกณฑ์ TC เดิมเงียบ ๆ

## 2 ข้อมูลทดสอบและ API ที่อ้างอิง

ข้อมูลเป็นบัญชีและผลงานสมมติในสภาพแวดล้อมทดสอบ ให้สร้าง session ทดสอบจริงหรือ mock ตามระดับการทดสอบ ไม่ใช้ชื่อ alias แทน token และไม่บันทึกรหัสผ่าน TU หรือ token จริงในหลักฐาน

| ข้อมูล | แนวข้อสอบ | สรุป PDF |
| --- | --- | --- |
| ผลงานเป้าหมาย | guide_id = 42 วิชา CS261 | summary_id = 101 วิชา CS261 |
| เจ้าของผลงาน P | user id 22 ชื่อ reader | user id 11 ชื่อ owner |
| ผู้รีวิว R | user id 11 ชื่อ owner | user id 22 ชื่อ reader |
| บัญชีอื่น X | user id 33 ชื่อ other | user id 33 ชื่อ other |
| รีวิวเดิมของ R สำหรับกรณีแก้หรือลบ | review_id = 502 | review_id = 501 |
| ID ที่ไม่มีอยู่ | 999999 และตรวจว่าไม่ถูก seed | 999999 และตรวจว่าไม่ถูก seed |

ชื่อ owner และ reader เป็น alias ของ fixtures ไม่ใช่สิทธิ์ถาวร ให้ใช้บทบาท P และ R ตามชนิดผลงานในตารางเสมอ ใช้ review_id เป็นจำนวนเต็มจริง ไม่ส่งชื่อ G1 หรือ R1 ใน path ล้างและเตรียมข้อมูลใหม่ก่อนแต่ละกรณีย่อย เว้นแต่กรณีนั้นกำหนดให้ทำต่อกัน

| การทำงาน | เส้นทางตาม Task94 | ผลตั้งต้น |
| --- | --- | --- |
| ดูหรือเพิ่มรีวิว guide | GET หรือ POST /api/guides/{guide_id}/reviews | 200 list หรือ 201 review |
| ดูหรือเพิ่มรีวิว summary | GET หรือ POST /api/summaries/{summary_id}/reviews | 200 list หรือ 201 review |
| แก้ไขรีวิว | PUT /api/reviews/{review_id} | 200 ReviewDTO |
| ลบรีวิว | DELETE /api/reviews/{review_id} | 204 ไม่มี body |

ทุกเส้นใช้ Bearer token ที่ใช้ได้ ReviewWriteRequest มี rating กับ comment ส่วน ReviewDTO มี id, target_type, target_id, rating, comment, author, created_at และ updated_at Error ใช้ {error: {code, message, fields}} โดย fields เป็น array เสมอ รายละเอียด schema ให้อ้าง contract ไม่กำหนด schema ชุดใหม่ใน Task97

Task94 อ้างจาก PR #103 commit de3e669 รุ่น 0.2 ซึ่งยังเป็นเอกสารส่งตรวจในขณะจัดทำ Task97 การอ้างนี้ไม่ถือว่า Task94 ผ่าน DoD หรือ PO อนุมัติแล้ว

## 3 กรณีให้คะแนนสำเร็จ

### U8-TC01 ให้คะแนนพร้อมข้อความสำเร็จ

สถานะ ยังไม่ทดสอบ

Given  R Login และเปิดอ่านผลงานของ P ผลงานยังมีอยู่ และ R ยังไม่เคยรีวิวผลงานนั้น

When  เลือก 5 ดาว ใส่ข้อความ “อ่านง่ายและตรงประเด็น” แล้วส่ง จากนั้นโหลดหน้าอ่านใหม่และให้ X Login เปิดผลงานเดียวกัน

Then  แสดง 5 ดาว ข้อความ ผู้รีวิว และผลงานตรงรายการที่ส่ง ข้อมูลยังอยู่หลังโหลดใหม่และผู้ใช้อื่นอ่านได้ ไม่ไปแสดงบนผลงานอื่น ทำแยกกับ guide 42 และ summary 101

API ตามแบบ Task94  POST 201 ReviewDTO จากนั้น GET 200 รายการที่มีรีวิวเดิม id เดียวกัน

Fixtures ที่อ้าง  u8-guide-create และ u8-summary-create

### U8-TC02 ให้ดาวโดยไม่เขียนข้อความได้

สถานะ ยังไม่ทดสอบ

Given  R Login สามารถรีวิวผลงานของ P และยังไม่มีรีวิวในผลงานนั้น

When  ให้ 1 ดาวโดยไม่ส่ง comment แล้วตรวจผล เริ่มข้อมูลใหม่ก่อนทดสอบ 5 ดาวโดยไม่ส่ง comment ทำทั้งสองคะแนนกับผลงานทั้งสองชนิด

Then  บันทึกได้ ไม่บังคับกรอกข้อความ แสดงคะแนนถูกต้องหลังโหลดใหม่ ตาม Task94 ให้ comment เป็น null ไม่สร้างข้อความปลอมแทนช่องว่าง

API ตามแบบ Task94  POST 201 เมื่อ rating เป็น 1 หรือ 5 และไม่มี comment

Fixtures ที่อ้าง  u8-guide-stars-1, u8-guide-stars-5, u8-summary-stars-1, u8-summary-stars-5

## 4 กรณีคะแนนไม่ถูกต้องและแก้ไข

### U8-TC03 คะแนนไม่ถูกต้องต้องไม่บันทึก

สถานะ ยังไม่ทดสอบ

Given  R Login อยู่หน้าส่งรีวิว สำหรับการแก้ไขให้เตรียมรีวิวเดิม 4 ดาวและข้อความ “เดิม” ของ R ไว้ก่อน

When  ทดสอบไม่เลือกหรือไม่ส่ง rating, 0, 6, -1 และ 2.5 ทีละค่า ทั้งตอนเพิ่มและแก้ไข และทั้ง guide กับ summary แยกกัน เริ่มข้อมูลเดิมใหม่ก่อนแต่ละกรณีย่อย

Then  แจ้งให้เลือกคะแนนเต็ม 1 ถึง 5 ไม่สร้างรีวิวเมื่อเพิ่มไม่สำเร็จ ตอนแก้ต้องคงคะแนนและข้อความเดิม ไม่เปลี่ยนรีวิวอื่น การปิดปุ่มใน UI ไม่แทนการตรวจ Backend

API ตามแบบ Task94  POST หรือ PUT 422 INVALID_PARAMETERS โดย fields ระบุ rating และไม่มีการบันทึก

Fixtures ที่อ้าง  u8-guide-invalid-* และ u8-summary-invalid-* เป็นตัวอย่าง POST ส่วน PUT ต้องเพิ่มกรณีใน test harness ตามเงื่อนไขด้านบน

### U8-TC04 แก้ไขรีวิวของตน

สถานะ ยังไม่ทดสอบ

Given  R Login และมีรีวิวเดิมของตนในผลงานที่ยังอยู่ เช่น 5 ดาวและข้อความเดิม

When  ทดสอบแก้ดาวอย่างเดียว แก้ข้อความอย่างเดียว และแก้ทั้งสองอย่างแยกกัน แล้วโหลดใหม่ สำหรับ PUT ส่งค่าที่ต้องการคงไว้กลับไปด้วย

Then  แสดงข้อมูลล่าสุดหลังโหลดใหม่ review_id ผู้รีวิวและผลงานเป้าหมายคงเดิม ไม่เพิ่มจำนวนรีวิว ตัวอย่างเปลี่ยนเป็น 4 ดาวและล้าง comment ด้วย null ต้องยังเป็นรีวิวเดิม

API ตามแบบ Task94  PUT 200 ReviewDTO และ GET 200 ต้องเห็นค่าใหม่ ใช้ id 502 สำหรับ guide หรือ 501 สำหรับ summary

Fixtures ที่อ้าง  u8-guide-update และ u8-summary-update

## 5 กรณีลบและสิทธิ์จัดการ

### U8-TC05 ลบรีวิวของตน

สถานะ ยังไม่ทดสอบ

Given  R Login มีรีวิวของตน และเตรียมรีวิวอีกหนึ่งรายการของ X บนผลงานเดียวกัน

When  R ลบรีวิวของตน แล้วโหลดรายการรีวิวใหม่ ทดสอบแยกสำหรับ guide และ summary

Then  รีวิวของ R หายหลังโหลดใหม่ รีวิวของ X และตัวผลงานยังอยู่ ไม่ลบข้อมูลของผู้ใช้อื่น ไฟล์และรายวิชาไม่เปลี่ยน

API ตามแบบ Task94  DELETE 204 ไม่มี JSON body จากนั้น GET 200 ไม่มี review_id ที่ลบ แต่ยังมีรีวิวของ X

Fixtures ที่อ้าง  u8-guide-delete และ u8-summary-delete ต้องเพิ่มรีวิว X ใน setup ของ test นี้เพื่อพิสูจน์ว่าไม่ลบของผู้อื่น

### U8-TC06 แก้ไขหรือลบรีวิวของผู้อื่นไม่ได้

สถานะ ยังไม่ทดสอบ

Given  เตรียมรีวิวของ R บนผลงานของ P และบัญชี X ที่ไม่ใช่เจ้าของรีวิว

When  X ส่ง PUT และ DELETE ตรงไป Backend ต่อรีวิวของ R ทดสอบไม่มี token และ token หมดอายุสำหรับ POST PUT DELETE แยกกัน รวม POST และ PUT ที่ปลอม author_id หรือชื่อผู้รีวิวคนอื่นใน body

Then  ปฏิเสธคำขอที่ไม่มีสิทธิ์ ไม่เปลี่ยนรีวิวของ R ไม่สร้างรีวิวในชื่อผู้อื่น Backend ผูกผู้รีวิวกับ session เท่านั้น การอ่านรีวิวของผู้อื่นยังทำได้เมื่อ Login

API ตามแบบ Task94  X แก้หรือลบได้ 403 REVIEW_FORBIDDEN ไม่มีหรือใช้ token ไม่ได้ตอบ 401 AUTH_REQUIRED ฟิลด์ปลอมที่ไม่อยู่ใน schema ตอบ 422 INVALID_PARAMETERS

Fixtures ที่อ้าง  u8-guide-permissions และ u8-summary-permissions เป็นตัวอย่างบางกรณี ต้องเพิ่ม token ที่ใช้ไม่ได้สำหรับ PUT DELETE และการปลอม author ใน PUT ตามข้อกำหนดนี้

## 6 กติกาที่เสนอเพิ่มเติม

TC07 และ TC08 คงรหัสและข้อความตาม Story เดิม แต่ยังเป็นข้อเสนอที่ต้องให้ทีมและ PO ยืนยันก่อนใช้เป็นเกณฑ์ตรวจรับ ไม่บันทึกว่าผ่านการยืนยันแล้วจากการที่มี API contract

### U8-TC07 รีวิวผลงานของตนไม่ได้

สถานะ รอยืนยันกติกากับทีมและ PO และยังไม่ทดสอบ

Given  P Login และเป็นเจ้าของผลงานเป้าหมายจริง ไม่ใช่การอ้างชื่อเจ้าของจาก client

When  P พยายามเพิ่มรีวิวผลงานของตนผ่าน UI และส่ง POST ตรงไป Backend ทำแยกกับ guide และ summary

Then  เมื่อทีมยืนยันกติกานี้แล้ว ต้องแจ้งว่ารีวิวงานตนเองไม่ได้ ไม่สร้างรีวิวและไม่เปลี่ยนงานอื่น

API ตามแบบ Task94  ข้อเสนอตาม Task94 ตอบ 403 SELF_REVIEW_FORBIDDEN

Fixtures ที่อ้าง  u8-guide-self และ u8-summary-self

สถานะ รอยืนยันกติกากับทีมและ PO และยังไม่ทดสอบ

Given  R Login และมีรีวิวอยู่แล้วบนผลงานของ P

When  ส่ง POST ใหม่ในผลงานชนิดและ id เดิมอีกครั้ง ทั้ง guide และ summary แยกกัน ไม่ใช้ PUT แทนกรณีทดสอบการเพิ่มซ้ำ

Then  เมื่อทีมยืนยันกติกานี้แล้ว ต้องมีรีวิวของ R เพียงหนึ่งรายการ ไม่เปลี่ยนรีวิวเดิมจาก POST ซ้ำ และแนะนำให้แก้ไขรีวิวเดิม งานต่างชนิดที่มีเลข id เท่ากันยังถือเป็นคนละผลงาน

API ตามแบบ Task94  ข้อเสนอตาม Task94 ตอบ 409 REVIEW_ALREADY_EXISTS ส่วนการแก้ไขใช้ PUT กับ review_id เดิม

Fixtures ที่อ้าง  u8-guide-duplicate และ u8-summary-duplicate

## 7 กรณีไม่พบผลงานและระบบล้มเหลว

### U8-TC09 ไม่พบผลงานหรือบันทึกรีวิวไม่สำเร็จ

สถานะ ยังไม่ทดสอบ

Given  R Login เตรียมกรณีผลงานถูกลบแล้วแยกจากกรณีผลงานยังอยู่แต่จำลอง storage ล้มเหลวก่อนสำเร็จ การแก้หรือลบต้องมีรีวิวของ R ก่อนจำลองเหตุ

When  ทดสอบเพิ่มรีวิวให้ target ที่ถูกลบ จากนั้นทดสอบแก้และลบรีวิวที่ไม่พบหรือ target ถูกลบ จำลองให้เพิ่ม แก้ และลบล้มเหลวทีละแบบ ทำทุกกรณีกับ guide และ summary แยกกัน

Then  แจ้งไม่พบรายการหรือทำรายการไม่สำเร็จตรงเหตุ ไม่แจ้งสำเร็จลวง ไม่สร้างงานที่ลบแล้วกลับมา ไม่เปลี่ยนรีวิวของผลงานอื่น กรณีบันทึกล้มเหลวก่อนสำเร็จต้องไม่เกิดรีวิวใหม่หรือคงข้อมูลเดิมตามการกระทำ

API ตามแบบ Task94  POST target หายตอบ 404 GUIDE_NOT_FOUND หรือ SUMMARY_NOT_FOUND PUT และ DELETE รีวิวหายตอบ 404 REVIEW_NOT_FOUND Storage ล้มเหลวตอบ 503 STORAGE_UNAVAILABLE

Fixtures ที่อ้าง  u8-guide-missing, u8-summary-missing และ u8-{guide|summary}-storage-{create|update|delete}

### Definition of Done และ Artefact

ไฟล์ส่งมอบคือ Markdown และ DOCX ใน docs/U8/requirements/ ซึ่งรวมบันทึกผลตรวจและแนวทางรอ PO ยืนยันไว้ในเอกสารเดียวกัน ยังไม่ติ๊ก artefact ที่ระบุว่า “ยืนยันแล้ว” หรือ DoD เรื่องยืนยัน Requirement จนกว่าจะมีมติและหลักฐานจริง ไม่ถือว่า TC ใดผ่านการทดสอบระบบแล้ว
