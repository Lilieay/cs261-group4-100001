# Task123 เตรียมทดสอบ Integration U9

อิง Task103 และ Task94 รุ่น 0.4 ทดสอบการบันทึกแนวข้อสอบหรือสรุป PDF ทีละชิ้น รายวิชาใช้จัดกลุ่ม ส่วนหน้าเปิดรายการที่บันทึกเป็นงาน U10

## ข้อมูลทดสอบ

ใช้ Docker Compose เดิมใน project แยก พร้อม SQL Server และ PDF volume ของชุดทดสอบ ใช้ TU mock สองบัญชีและตรวจว่ามี user ID ต่างกันใน SQL Server สร้างแนวข้อสอบหนึ่งชิ้นและ PDF หนึ่งชิ้นในวิชาเดียวกัน ตั้งชื่อขึ้นต้น `Task123-<timestamp>` แล้วจด ID ที่สร้างไว้สำหรับคืนข้อมูล

| กรณี | ผลที่ต้องตรวจ |
| --- | --- |
| เปิดหน้า Guide และ PDF ด้วยบัญชี A | GET สถานะได้ `200 saved:false` กดบันทึกแล้ว PUT ได้ `200 saved:true` และปุ่มแสดงว่าบันทึกแล้ว |
| กดซ้ำและส่ง PUT พร้อมกัน | ทั้งสองคำขอได้ `200 saved:true` และ SQL มี bookmark แถวเดียวต่อบัญชีและผลงาน |
| เปิดด้วยบัญชี B แล้วกลับมาล็อกอิน A ใหม่ | B ยังได้ `saved:false` ส่วน A ยังได้ `saved:true` หลัง reload และล็อกอินใหม่ |
| ผลงานถูกลบหรือยังไม่ได้ล็อกอิน | GET และ PUT ของผลงานที่หายได้ `404` ตามชนิด ไม่มี bookmark ใหม่ คำขอที่ไม่มี session ได้ `401` |
| SQL ปฏิเสธการเขียน | ใช้ trigger ครอบเฉพาะ ID ทดสอบ ตรวจว่า PUT ได้ `503 SAVED_ITEMS_UNAVAILABLE` แล้วอ่านสถานะใหม่ เปรียบเทียบแถวก่อนและหลัง |
| ยังยืนยันผลคำขอไม่ได้ | ให้หน้าอ่านร้องขอ GET สถานะใหม่และแสดงสถานะที่อ่านได้ พร้อมแจ้งว่าผล PUT เดิมยังยืนยันไม่ได้ |

หลังรัน ลบ trigger ใน `finally` ลบเฉพาะ bookmark และผลงานที่ชุดทดสอบสร้าง แล้วเทียบ SQL กับไฟล์ PDF ก่อนและหลัง เก็บ SHA, รุ่น Docker/SQL Server/เบราว์เซอร์, โหมด TU mock และหลักฐานของแต่ละเคส
