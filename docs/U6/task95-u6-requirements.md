## 2. User Story

**As a:** นักศึกษามหาวิทยาลัยธรรมศาสตร์ที่ต้องการแบ่งปันสรุปการเรียนรายวิชา CS

**I want to:** เลือกรายวิชา กรอกชื่อสรุป และอัปโหลดไฟล์ PDF พร้อมข้อมูลประกอบตามต้องการ แล้วเผยแพร่ให้ผู้ใช้อื่นเปิดอ่านไฟล์นั้นจากหน้ารายวิชาได้

**So that:** นักศึกษาที่กำลังเตรียมสอบสามารถเข้าถึงและใช้สรุปที่ฉันแบ่งปันเพื่อทบทวนเนื้อหาของวิชานั้นได้

## 3. Requirements and Business Rules

### 3.1 Required and Optional Information

| Field | Requirement | Validation / Expected Behavior |
|---|---|---|
| รายวิชา | Required | ต้องเลือกรายวิชาที่มีอยู่จริงและอยู่ในขอบเขต CS ที่ระบบอนุญาต |
| ชื่อสรุป | Required | ต้องไม่เป็นค่าว่างหรือมีแต่ช่องว่าง |
| ไฟล์ PDF | Required | ต้องแนบไฟล์ PDF ที่ผ่านเงื่อนไขของระบบ |
| คำแนะนำเพิ่มเติม | Optional | สามารถเว้นว่างได้ |

**หมายเหตุ**
- ข้อมูลบังคับประกอบด้วย รายวิชา ชื่อสรุป และไฟล์ PDF
- ไม่มีช่องข้อมูลชื่อ "ประเภท"
- คำแนะนำเพิ่มเติมเป็นข้อมูลเสริมที่สามารถเว้นว่างได้

### 3.2 PDF File Rules

| Rule | Requirement | Status |
|---|---|---|
| File type | รับเฉพาะไฟล์ PDF ที่ตรวจสอบเนื้อหาไฟล์ได้ว่าเป็น PDF จริง ไม่ใช่ตรวจสอบจากนามสกุลเพียงอย่างเดียว | PO Confirmed |
| Maximum file size | ไม่เกิน 15 MB หรือ 15,000,000 bytes | PO Confirmed |
| Invalid extension | ไฟล์ที่ไม่ใช่ PDF แต่เปลี่ยนนามสกุลเป็น `.pdf` ต้องไม่ผ่าน | PO Confirmed |
| Oversized file | ไฟล์ที่มีขนาดเกิน 15 MB ต้องไม่ผ่าน | PO Confirmed |
| Error handling | แจ้งสาเหตุที่ผู้ใช้สามารถแก้ไขได้ และไม่เผยแพร่รายการ | PO Confirmed |

**วิธีตรวจสอบไฟล์ PDF**
1. ตรวจสอบ PDF Signature (`%PDF-`)
2. ตรวจสอบว่าไฟล์สามารถ Parse หรือเปิดอ่านได้จริง
3. หากไม่ผ่านเงื่อนไข ให้ปฏิเสธไฟล์และแจ้งข้อความ "ประเภทไฟล์ไม่ถูกต้อง"

### 3.3 Authorization and Access Rules

1. ผู้เผยแพร่ต้องเข้าสู่ระบบด้วยสถานะ Login ที่ใช้งานได้
2. เจ้าของสรุปต้องเป็นผู้ใช้ที่ระบบระบุตัวตนจากข้อมูลยืนยันตัวตน ไม่เชื่อถือ Owner ID ที่ผู้ใช้ส่งมาเอง
3. ต้องตรวจสอบว่ารายวิชามีอยู่จริงและอยู่ในขอบเขตที่ระบบอนุญาต โดย Backend ต้องตรวจสอบเอง ไม่เชื่อข้อมูลจาก Frontend เพียงอย่างเดียว
4. ผู้ใช้ที่เข้าสู่ระบบแล้วสามารถเปิดอ่านสรุปที่เผยแพร่ในรายวิชาที่เกี่ยวข้องได้
5. ผู้ที่ไม่ได้เข้าสู่ระบบหรือมีสถานะ Login ไม่ถูกต้อง ต้องไม่ได้รับข้อมูลรายการสรุปหรือเนื้อหา PDF ผ่านช่องทางที่ต้องมีการยืนยันตัวตน
6. รายการสรุปต้องแสดงในรายวิชาที่ตรงกับรายวิชาที่บันทึกไว้เท่านั้น

**เงื่อนไขการตรวจสอบรายวิชา**
- `course_id` ต้องเป็นจำนวนเต็มบวกในช่วงที่กำหนด
- รายวิชาต้องมีอยู่จริงในฐานข้อมูล
- รหัสวิชาต้องขึ้นต้นด้วย `CS`
- Backend ต้องตรวจสอบเงื่อนไขทั้งหมดด้วยตนเอง
- วิชาที่ไม่มีเนื้อหาก็สามารถเผยแพร่สรุปได้

**Expected Error Response**

| Condition | Expected Response |
|---|---|
| Course ID ไม่มีรูปแบบที่ถูกต้อง | `422 INVALID_PARAMETERS` |
| รายวิชาไม่มีอยู่จริงหรืออยู่นอกขอบเขต CS | `404 COURSE_NOT_FOUND` |

### 3.4 Publishing and Failure Rules

**Successful Publishing**

- ระบบบันทึกข้อมูลสรุปและไฟล์ได้ครบถ้วน
- รายการปรากฏในรายวิชาที่เลือก
- ผู้ใช้อื่นที่เข้าสู่ระบบสามารถเปิดอ่านไฟล์ตามสิทธิ์ที่กำหนด
- รายการยังคงอยู่หลังโหลดหน้าใหม่

**Failed Publishing**

- ระบบต้องแจ้งว่าเผยแพร่ไม่สำเร็จเมื่อการบันทึกข้อมูลหรือไฟล์ล้มเหลว
- ระบบต้องไม่แสดงข้อความสำเร็จหากการเผยแพร่ไม่สมบูรณ์
- ต้องไม่มีรายการสรุปที่เผยแพร่ค้างไว้โดยไม่มีไฟล์หรือข้อมูลที่จำเป็น
- หากบันทึกไฟล์หรือข้อมูลล้มเหลว ต้องมีวิธีจัดการข้อมูลและไฟล์ที่บันทึกไปแล้วให้ชัดเจน

**แนวทางจัดการเมื่อเกิดข้อผิดพลาด**

1. เก็บไฟล์ไว้ในพื้นที่ชั่วคราว
2. ตรวจสอบความถูกต้องของไฟล์
3. บันทึกข้อมูลด้วย Database Transaction
4. หากขั้นตอนใดล้มเหลว ต้อง Rollback ข้อมูลและจัดการไฟล์ที่ค้างไว้
5. ต้องไม่มีรายการเผยแพร่ที่ข้อมูลหรือไฟล์ไม่ครบถ้วน

หมายเหตุ: Database Transaction ไม่สามารถ Rollback ไฟล์ได้โดยอัตโนมัติ จึงต้องออกแบบการจัดการไฟล์ชดเชยเพิ่มเติม รายละเอียดอยู่ใน Task100 และพัฒนาใน Task110

## 5. U6 Test Cases

**User Story:** U6 – เผยแพร่สรุป PDF รายวิชา CS ให้ผู้ใช้อื่นเปิดอ่าน

**Test Status:** ยังไม่ได้ทดสอบ

### U6-TC01: เผยแพร่สำเร็จและผู้อื่นเปิดอ่านได้

- **ข้อมูลตั้งต้น:** นักศึกษา A เข้าสู่ระบบ และมีวิชา CS261
- **ข้อมูลทดสอบ:** วิชา CS261, ชื่อสรุป CS261 Summary, ไฟล์ PDF ที่ถูกต้อง
- **ขั้นตอน:** กรอกข้อมูลและเผยแพร่ จากนั้นให้นักศึกษา B เข้าสู่ระบบเพื่อเปิดอ่านหลังโหลดหน้าใหม่
- **ผลคาดหวัง:** เผยแพร่สำเร็จ สรุปแสดงใน CS261 และนักศึกษา B เปิดอ่านได้

### U6-TC02: เว้นข้อมูลประกอบได้

- **ข้อมูลตั้งต้น:** นักศึกษาเข้าสู่ระบบและมีวิชา CS261
- **ข้อมูลทดสอบ:** ชื่อสรุปและ PDF ที่ถูกต้อง โดยเว้นช่องคำแนะนำเพิ่มเติม
- **ขั้นตอน:** กรอกข้อมูลบังคับ แนบ PDF และเผยแพร่
- **ผลคาดหวัง:** เผยแพร่สำเร็จและเปิดอ่านได้ โดยไม่บังคับกรอกคำแนะนำเพิ่มเติม

### U6-TC03: ข้อมูลบังคับไม่ครบ

- **ข้อมูลตั้งต้น:** นักศึกษาเข้าสู่ระบบและอยู่หน้าฟอร์มเผยแพร่
- **ข้อมูลทดสอบ:** ทดสอบแยกกรณีไม่เลือกวิชา ไม่กรอกชื่อ ชื่อเป็นช่องว่าง และไม่แนบไฟล์
- **ขั้นตอน:** ส่งฟอร์มโดยขาดข้อมูลแต่ละกรณี
- **ผลคาดหวัง:** แจ้งข้อผิดพลาดที่เกี่ยวข้องและไม่สร้างรายการสรุป

### U6-TC04: ไฟล์ไม่ผ่านเงื่อนไข

- **ข้อมูลตั้งต้น:** นักศึกษาเข้าสู่ระบบแล้ว
- **ข้อมูลทดสอบ:** ไฟล์ที่ไม่ใช่ PDF, ไฟล์อื่นที่เปลี่ยนนามสกุลเป็น `.pdf` และ PDF ที่มีขนาดเกิน 15 MB
- **ขั้นตอน:** ทดสอบแนบไฟล์แต่ละกรณีและกดเผยแพร่
- **ผลคาดหวัง:** แจ้งว่าไฟล์ไม่ผ่านเงื่อนไขและไม่เผยแพร่สรุป

### U6-TC05: รายวิชาไม่ถูกต้องหรือปลอมชื่อเจ้าของ

- **ข้อมูลตั้งต้น:** นักศึกษา A เข้าสู่ระบบแล้ว
- **ข้อมูลทดสอบ:** ส่ง Request โดยตรงไป Backend ด้วย ID วิชาที่ไม่มีอยู่จริง วิชานอกขอบเขต CS และ ID เจ้าของเป็นนักศึกษา B
- **ขั้นตอน:** ส่ง Request แยกแต่ละกรณี
- **ผลคาดหวัง:** Backend ปฏิเสธข้อมูลที่ไม่ถูกต้องและไม่อนุญาตให้สร้างสรุปในชื่อผู้อื่น

### U6-TC06: ผู้ไม่ได้เข้าสู่ระบบเปิดสรุปไม่ได้

- **ข้อมูลตั้งต้น:** มีรายการสรุปที่เผยแพร่แล้ว
- **ข้อมูลทดสอบ:** ไม่มี Token และ Token ไม่ถูกต้องหรือหมดอายุ
- **ขั้นตอน:** เปิดรายการสรุป หน้าอ่าน และไฟล์ PDF โดยตรง แยกทดสอบแต่ละกรณี
- **ผลคาดหวัง:** ระบบปฏิเสธการเข้าถึง ไม่ส่งข้อมูลหรือไฟล์ที่ต้องป้องกัน และแจ้งให้เข้าสู่ระบบตาม Contract

### U6-TC07: เผยแพร่ล้มเหลว

- **ข้อมูลตั้งต้น:** นักศึกษาเข้าสู่ระบบและสามารถจำลองความล้มเหลวได้
- **ข้อมูลทดสอบ:** จำลองการบันทึกไฟล์ล้มเหลวและการบันทึกข้อมูลล้มเหลว แยกกัน
- **ขั้นตอน:** ส่งฟอร์มเผยแพร่ในแต่ละกรณี
- **ผลคาดหวัง:** แจ้งเผยแพร่ไม่สำเร็จ ไม่แสดงข้อความสำเร็จ และไม่มีรายการสรุปที่เผยแพร่ค้างอยู่โดยไม่สมบูรณ์

### U6-TC08: รายการสรุปตรงกับรายวิชา

- **ข้อมูลตั้งต้น:** CS261 มีสรุป และ CS104 ยังไม่มีสรุป
- **ข้อมูลทดสอบ:** รายวิชา CS261 และ CS104
- **ขั้นตอน:** นักศึกษาที่เข้าสู่ระบบเปิดหน้าของทั้งสองวิชาแยกกัน
- **ผลคาดหวัง:** CS261 แสดงเฉพาะสรุปของ CS261 ส่วน CS104 แสดงข้อความ "ไม่พบสรุปในรายวิชานี้" โดยไม่แสดงข้อมูลจากวิชาอื่น
