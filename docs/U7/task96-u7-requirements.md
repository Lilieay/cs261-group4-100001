## 2. User Story

**As a:** นักศึกษามหาวิทยาลัยธรรมศาสตร์ที่แบ่งปันสรุป PDF รายวิชา CS

**I want to:** เปิดหน้าสรุปของฉันเพื่อดูรายการและเปิดอ่านไฟล์ที่เคยเผยแพร่ รวมทั้งแก้ไขชื่อหรือข้อมูลประกอบ และลบรายการสรุปของตนเองได้

**So that:** ฉันสามารถตรวจสอบและจัดการข้อมูลสรุปที่แชร์ไว้ รวมถึงนำข้อมูลสรุปที่ไม่ต้องการเผยแพร่ออกได้ในที่เดียว

## 3. Scope of Task96

ครอบคลุมกติกาและกรณีทดสอบสำหรับ:

- ดูเฉพาะรายการสรุปที่ผู้ใช้ปัจจุบันเป็นเจ้าของ
- เปิดอ่าน PDF ของรายการที่ตนเผยแพร่
- แก้ไขชื่อและข้อมูลประกอบตามช่องที่ตกลงกัน
- คงรายการเดิมและไฟล์ PDF เดิมหลังแก้ไข หากไม่มีการอัปโหลดไฟล์ใหม่
- ยืนยันหรืองดลบรายการ
- ป้องกันผู้ใช้ที่ไม่ใช่เจ้าของแก้ไขหรือลบ
- จัดการกรณีรายการไม่พบหรือการบันทึกล้มเหลว

ตามมติ PO ล่าสุด อนุญาตให้แก้ไขรายวิชาและเปลี่ยนไฟล์ PDF ได้ด้วย โดยรายละเอียดต้องสอดคล้องกับ API Contract รุ่นถัดไป

## 5. Requirements and Business Rules

### 5.1 Business Rules

| ID | ข้อกำหนด | ที่มาและสถานะ |
|---|---|---|
| R01 | ผู้ใช้ต้อง Login ก่อนเข้าหน้าจัดการสรุปของตน | U7-TC01, TC02, TC07; ตรวจ Contract |
| R02 | รายการในหน้าสรุปของฉันต้องกรองจากเจ้าของที่ได้จาก Session ปัจจุบัน ไม่รับ Owner ID จากผู้ใช้เพื่อเลือกดูผลงาน | U7-TC01, TC07 |
| R03 | เจ้าของเปิดอ่าน PDF ของรายการตนเองได้ | U7-TC01 |
| R04 | แก้ไขชื่อและช่องข้อมูลประกอบที่ตกลงกันได้ โดยคง ID รายการและเจ้าของเดิม เว้นแต่มีการเปลี่ยนแปลงตามมติ PO | U7-TC03 |
| R05 | ชื่อสรุปต้องไม่ว่างหรือเป็นช่องว่างล้วน | U7-TC04; ตรวจสอบข้อกำหนด Validation กับ Contract |
| R06 | ลบได้เฉพาะรายการของเจ้าของ และต้องยืนยันก่อนส่งคำสั่งลบจาก UI | U7-TC05, TC06 |
| R07 | เมื่อยกเลิกคำสั่งลบ ต้องไม่ส่งคำสั่งลบและข้อมูลเดิมยังอยู่ | U7-TC06 |
| R08 | ผู้ที่ไม่ใช่เจ้าของหรือไม่มี Session ที่ใช้ได้ต้องแก้ไข/ลบไม่ได้ แม้ส่งคำขอตรงไป Backend | U7-TC07 |
| R09 | เมื่อรายการถูกลบหรือการบันทึกล้มเหลว ต้องไม่แจ้งสำเร็จผิด และต้องไม่สร้างรายการที่ลบแล้วกลับมา | U7-TC08 |

### 5.2 Information That Can Be Viewed and Edited

| ข้อมูล | กติกา | สถานะ |
|---|---|---|
| รายการสรุป | แสดงเฉพาะรายการที่ผูกกับผู้ใช้ปัจจุบัน | ตรวจ Contract |
| ชื่อสรุป | แก้ไขได้ ความยาวไม่เกิน 200 ตัวอักษร | PO Confirmed |
| คำแนะนำเพิ่มเติม | แก้ไขได้ ความยาวไม่เกิน 2,000 ตัวอักษร และสามารถล้างค่าได้ | PO Confirmed |
| ไฟล์ PDF | สามารถเปลี่ยนไฟล์ได้โดยอัปโหลดไฟล์ใหม่ หากไม่แนบไฟล์ใหม่ให้คงไฟล์เดิม | PO Confirmed |
| รายวิชา | สามารถเปลี่ยนรายวิชาได้ | PO Confirmed |
| เจ้าของ | คงเจ้าของเดิมจากข้อมูลที่ระบบยืนยัน ไม่รับการเปลี่ยนเจ้าของจาก Request | Security Requirement |
| ข้อมูลอื่น เช่น Created Date | ไม่แก้ไข เว้นแต่ Contract ระบุเป็นอย่างอื่น | ตรวจ Contract |

**ข้อกำหนดเพิ่มเติม**
- หากผู้ใช้ไม่อัปโหลด PDF ใหม่ ระบบต้องคงไฟล์เดิม
- หากเปลี่ยน PDF ไม่สำเร็จ ต้องยังสามารถใช้ข้อมูลและไฟล์เดิมได้
- ควรตรวจสอบ File ID, Storage Key หรือ Checksum เพื่อพิสูจน์ว่าเป็นไฟล์เดิมเมื่อไม่มีการเปลี่ยนไฟล์
- การแก้ไขต้องไม่ทำให้เกิดรายการสรุปซ้ำ

### 5.3 Authorization and Delete Rules

1. ผู้ใช้ต้อง Login ก่อนเข้าหน้าจัดการสรุปของตน
2. ผู้ใช้เห็นเฉพาะรายการที่เป็นเจ้าของ
3. Backend ต้องตรวจสอบสิทธิ์เจ้าของก่อนแก้ไขหรือลบ
4. ห้ามเชื่อถือ Owner ID ที่ส่งมาจาก Frontend
5. เมื่อยืนยันลบ ระบบต้องนำรายการออกจากหน้าของฉันและหน้ารายวิชาตามข้อกำหนด
6. หลังลบต้องไม่สามารถเปิด PDF ผ่านระบบได้อีก
7. การลบรายการต้องไม่ลบรายวิชา สรุปอื่น หรือข้อมูลของเจ้าของคนอื่น
8. ตามมติ PO ต้องลบไฟล์จริงออกจาก Storage ด้วย

}

## 7. U7 Test Cases

**User Story:** U7 – ดู แก้ไขข้อมูล และลบสรุป PDF ของฉัน

**Test Status:** Not Run

### U7-TC01: ดูและเปิดอ่านเฉพาะสรุปของตน

- **ข้อมูลตั้งต้น:** A Login แล้ว มี S1 ของตน และมี S2 ของ B ในวิชาเดียวกัน
- **ข้อมูลทดสอบ:** เปิดหน้าสรุปของฉันด้วย Session ของ A แล้วเลือก S1
- **ขั้นตอน:** โหลดรายการของ A แล้วเปิด PDF ของ S1
- **ผลคาดหวัง:** แสดงเฉพาะรายการของ A ไม่แสดง S2 และเปิด PDF ที่ตรงกับ S1 ได้
- **Actual Result:** ยังไม่ได้ทดสอบ
- **หลักฐาน:** รอหลักฐานหน้ารายการและการเปิด PDF

### U7-TC02: ยังไม่เคยเผยแพร่สรุป

- **ข้อมูลตั้งต้น:** A Login แล้ว และไม่มีสรุปที่เป็นเจ้าของในฐานข้อมูลทดสอบ
- **ข้อมูลทดสอบ:** เปิดหน้าสรุปของฉันของ A
- **ขั้นตอน:** โหลดหน้ารายการ
- **ผลคาดหวัง:** แสดงข้อความ "คุณยังไม่ได้แบ่งปันสรุป PDF" และมีปุ่ม "แบ่งปันสรุป" เพื่อไปยังหน้าฟอร์มเผยแพร่สรุป PDF
- **Actual Result:** ยังไม่ได้ทดสอบ
- **หลักฐาน:** รอหลักฐาน Empty State และลิงก์ไปหน้าฟอร์ม

### U7-TC03: แก้ไขชื่อหรือข้อมูลประกอบสำเร็จ

- **ข้อมูลตั้งต้น:** A Login แล้วและเป็นเจ้าของ S1
- **ข้อมูลทดสอบ:** เปลี่ยนชื่อเป็น CS261 Summary Revised และเปลี่ยนข้อมูลประกอบที่อนุญาต
- **ขั้นตอน:** บันทึกการแก้ไข แล้ว Reload หน้าสรุปของฉัน หน้ารายวิชา และหน้าอ่านที่เกี่ยวข้อง
- **ผลคาดหวัง:** ทุกหน้าที่เกี่ยวข้องแสดงข้อมูลล่าสุดหลัง Reload ข้อมูลเจ้าของยังเป็น A และ PDF ยังคงเป็นไฟล์เดิมหากไม่ได้อัปโหลดไฟล์ใหม่ ไม่มีรายการซ้ำ
- **Actual Result:** ยังไม่ได้ทดสอบ
- **หลักฐาน:** รอภาพ/Response ก่อนและหลังแก้ พร้อมหลักฐานระบุตัวไฟล์

### U7-TC04: ชื่อสรุปไม่ถูกต้องต้องไม่บันทึก

- **ข้อมูลตั้งต้น:** A Login แล้วและเป็นเจ้าของ S1
- **ข้อมูลทดสอบ:** ทดสอบแยก (1) ตั้งชื่อเป็นค่าว่าง และ (2) ตั้งชื่อเป็นช่องว่างล้วน เช่น `" "`
- **ขั้นตอน:** ส่งการแก้ไขแต่ละกรณีแยกกัน
- **ผลคาดหวัง:** แจ้งให้กรอกชื่อ ชื่อและข้อมูลเดิมไม่เปลี่ยน และ PDF ยังคงใช้งานได้
- **Actual Result:** ยังไม่ได้ทดสอบ
- **หลักฐาน:** รอ Validation Response/UI และหลักฐานว่าข้อมูลเดิมไม่เปลี่ยน

### U7-TC05: ยืนยันลบสรุปของตน

- **ข้อมูลตั้งต้น:** A Login แล้วเป็นเจ้าของ S1 มี S2 ของ B และมีวิชา CS261 อยู่
- **ข้อมูลทดสอบ:** เลือก S1 แล้วกดยืนยันลบ
- **ขั้นตอน:** ยืนยันการลบ จากนั้น Reload หน้าของฉันและหน้าวิชา แล้วลองเปิด PDF ของ S1 ผ่าน URL/ช่องทางในระบบ
- **ผลคาดหวัง:** S1 หายจากหน้าของฉันและหน้าวิชาตาม Contract เปิด PDF ผ่านระบบไม่ได้อีก และ S2 กับรายวิชา CS261 ยังอยู่
- **Actual Result:** ยังไม่ได้ทดสอบ
- **หลักฐาน:** รอผลหน้ารายการก่อน/หลัง ผลเปิดไฟล์ และการตรวจว่าสรุปอื่น/รายวิชายังอยู่
- **หมายเหตุ:** ตามมติ PO ต้องลบไฟล์จริงจาก Storage ด้วย

### U7-TC06: ยกเลิกการลบแล้วสรุปยังอยู่

- **ข้อมูลตั้งต้น:** A Login แล้วเป็นเจ้าของ S1
- **ข้อมูลทดสอบ:** เปิดกล่องยืนยันการลบของ S1 แล้วเลือกยกเลิก
- **ขั้นตอน:** สังเกตการทำงานของ UI และตรวจรายการ/ไฟล์ภายหลัง
- **ผลคาดหวัง:** ไม่มีคำสั่งลบถูกส่ง S1 และข้อมูลเดิมยังอยู่ และเปิด PDF เดิมได้
- **Actual Result:** ยังไม่ได้ทดสอบ
- **หลักฐาน:** รอภาพกล่องยืนยัน ผลตรวจ Request และการเปิด PDF

### U7-TC07: ผู้ที่ไม่มีสิทธิ์จัดการสรุปไม่ได้

- **ข้อมูลตั้งต้น:** A เป็นเจ้าของ S1 และ B เป็นผู้ใช้คนละบัญชี เตรียมกรณีไม่มี Token และ Token ใช้ไม่ได้แยกจากกรณี B
- **ข้อมูลทดสอบ:**
  1. B ส่งคำขอแก้ไข S1 โดยตรง
  2. B ส่งคำขอลบ S1 โดยตรง
  3. ไม่มี Token หรือ Token ใช้ไม่ได้เรียกหน้าหรือ API สำหรับจัดการ
- **ขั้นตอน:** ส่งคำขอแต่ละแบบแยกกัน แล้วอ่านข้อมูล S1 และเปิด PDF ด้วย A
- **ผลคาดหวัง:** Backend ปฏิเสธการจัดการที่ไม่มีสิทธิ์ตาม Contract ข้อมูลและไฟล์ของ A ไม่เปลี่ยน ไม่สร้างรายการใหม่ และคำขอที่ไม่มีหรือ Token ใช้ไม่ได้ได้รับผลตามกติกา Authentication
- **Actual Result:** ยังไม่ได้ทดสอบ
- **หลักฐาน:** รอ Request/Response และการยืนยันว่า S1 ยังเหมือนเดิม
- **หมายเหตุ:** ห้ามกำหนด HTTP Status/Error Code จนกว่าจะตรวจ Contract Summary ที่ตกลงแล้ว

### U7-TC08: รายการหายหรือดำเนินการไม่สำเร็จ

- **ข้อมูลตั้งต้น:** เตรียมสรุปสำหรับกรณีรายการถูกลบไปแล้วจากอีกหน้าหนึ่ง และเตรียม S1 สำหรับจำลอง Update/Delete Failure
- **ข้อมูลทดสอบ:**
  1. แก้ไข S1 หลังถูกลบไปแล้ว
  2. ยืนยันลบรายการที่ถูกลบไปแล้ว
  3. จำลองการบันทึกแก้ไขล้มเหลว
  4. จำลองการลบล้มเหลว
- **ขั้นตอน:** ส่งคำขอแต่ละกรณีแยกกัน แล้วตรวจรายการ ข้อมูลเดิม และไฟล์
- **ผลคาดหวัง:**
  - แจ้งว่าไม่พบรายการหรือดำเนินการไม่สำเร็จตามเหตุและ Contract
  - ไม่แจ้งสำเร็จผิด
  - การแก้ไขที่ล้มเหลวไม่ทิ้งข้อมูลครึ่งชุด
  - รายการที่ลบแล้วไม่ถูกสร้างกลับมา
  - กรณีลบล้มเหลวให้ผลคงเหลือตรงกับนโยบาย Transaction ที่ทีมยืนยัน
- **Actual Result:** ยังไม่ได้ทดสอบ
- **หลักฐาน:** รอผลจำลอง Failure, Response/UI และผลตรวจรายการกับไฟล์หลังแต่ละกรณี
