## จุดที่ต้องยืนยันกับ PO ก่อนล็อก Story

ชื่อและคำอธิบาย U10 ระบุ “รายการรายวิชาส่วนตัว” และ “เปิดวิชา” ส่วนพฤติกรรมที่มีอยู่ในโค้ดเป็นการบันทึก **แนวข้อสอบรายรายการ** หน้า `saved-courses.html` แสดงรหัส/ชื่อวิชาคู่กับแนวข้อสอบ แต่ API และตารางเก็บ `guide_id` ไม่ได้บันทึก `course_id` เป็นรายการส่วนตัว จากข้อทบทวนล่าสุดต้องรองรับสรุป PDF เป็นผลงานอีกชนิด จัดกลุ่มผลงานตามวิชา และเปิดผลงานที่เลือกได้ตรงชิ้น โดยยังคงกรณีเปิดหน้าวิชาที่บันทึกไว้ตาม Story เดิม ทั้งนี้ route/DTO และมติ PO ยังรอยืนยัน

คำถามที่ต้องได้มติ:

1. ยืนยันรายการส่วนตัวเป็นผลงานรายชิ้น (แนวข้อสอบและสรุป PDF) ที่จัดกลุ่มตามรายวิชา และวิธีแสดงหน้าวิชาที่บันทึกไว้ตาม Story เดิม
2. ยืนยันเส้นทางเปิดหน้ารายวิชาและเส้นทางเปิดผลงานแต่ละชนิดที่เลือกจากวิชานั้น
3. ยืนยันว่าการนำออกลบเฉพาะ bookmark ของผู้ใช้ปัจจุบัน โดยคงผลงาน PDF และรายวิชา รวมถึง bookmark ของผู้ใช้อื่น
4. ยืนยัน route/DTO สำหรับผลงานสองชนิดร่วมกับ Task94; `/api/saved-guides` เป็น contract ปัจจุบันสำหรับแนวข้อสอบเท่านั้น

ข้อทบทวนกำหนดให้ทดสอบการเปิดทั้งหน้าวิชาและผลงานที่เลือก รวมถึงสรุป PDF แต่ยังไม่ใช่มติ PO หรือ API contract ที่อนุมัติ Frontend และ Backend ต้องทบทวน route/DTO กับ Task94 และบันทึกมติจริงก่อนล็อก Story

## Story ฉบับรอ PO ยืนยัน

> ในฐานะนักศึกษาที่เข้าสู่ระบบ ฉันต้องการดูรายวิชาที่มีผลงานบันทึกไว้ เปิดหน้าวิชาและผลงานที่เลือกได้ ทั้งแนวข้อสอบและสรุป PDF และนำผลงานที่ไม่ต้องการออกจากรายการส่วนตัว โดยไม่ลบผลงานต้นฉบับหรือรายวิชา

**หมายเหตุ:** ข้อความนี้เป็นร่างจาก Story เดิมร่วมกับข้อทบทวนล่าสุด ส่วนระบบปัจจุบันรองรับเฉพาะ Guide bookmark ยังไม่ถือเป็นมติ PO จนกว่าจะบันทึกผลการทบทวนด้านบน

## กติกาที่ตรวจสอบจากระบบปัจจุบัน

- ทุกการอ่าน/เพิ่ม/นำออกต้องมี Bearer Token ที่ยังใช้ได้; Backend ใช้ตัวตนจาก token ไม่รับ user id จากผู้เรียกเพื่อเลือกเจ้าของข้อมูล
- รายการส่วนตัวปัจจุบันเป็นรายการแนวข้อสอบที่บันทึกไว้ (`SavedGuide` ระบุ `user_id` และ `guide_id`)
- เพิ่มรายการเดิมซ้ำได้โดยผลยังเป็น saved และไม่สร้าง bookmark ซ้ำ
- เปิดจากรายการที่บันทึกจะนำไปยังแนวข้อสอบที่เลือก โดยแสดงข้อมูลล่าสุดจาก Guide และ Course
- นำรายการออกซ้ำได้; ผลสุดท้ายเป็น `saved: false`
- การนำออกลบเฉพาะ bookmark ของผู้ใช้นั้น ไม่ลบ Guide หรือ Course
- ถ้า Guide ถูกลบโดยกระบวนการที่มีสิทธิ์ bookmark ที่อ้างถึง Guide จะถูกลบตาม foreign key cascade
- ถ้าไม่พบ Guide ตอนเพิ่ม ระบบตอบ `404 GUIDE_NOT_FOUND`
- เมื่อ storage อ่าน/เขียนไม่ได้ ระบบตอบ `503 SAVED_GUIDES_UNAVAILABLE`; UI ต้องไม่แสดงว่าสำเร็จและควรโหลดสถานะใหม่ก่อนทำซ้ำ
- Endpoint ที่ใช้อยู่: `GET /api/saved-guides`, `GET /api/saved-guides/{guide_id}`, `PUT /api/saved-guides/{guide_id}`, `DELETE /api/saved-guides/{guide_id}`

## U10-TC01–TC07

ข้อมูลทดสอบทั้งหมดเป็นข้อมูลสังเคราะห์ในฐานข้อมูลทดสอบ ห้ามใช้บัญชี TU, password หรือ token จริงในหลักฐาน

| รหัส | ข้อมูล/เงื่อนไขทดสอบ | ขั้นตอนย่อ | ผลคาดหวัง |
|---|---|---|---|
| U10-TC01 เพิ่มรายการและเพิ่มซ้ำ | ผู้ใช้ A Login; มี Course `CS261` และ Guide `G1` ที่ยังอยู่ | `PUT /api/saved-guides/G1` สองครั้ง แล้วตรวจรายการและสถานะ | ทั้งสองครั้งตอบ `200 {id: G1, saved: true}`; มี bookmark ของ A ต่อ G1 เพียงหนึ่งรายการ; Course และ Guide ยังอยู่ |
| U10-TC02 เปิดหน้าวิชาและผลงานที่เลือก | ผู้ใช้ A บันทึก G1, G2 และสรุป PDF S1 ใน `CS261`; แต่ละชิ้นมีชื่อ/เนื้อหาต่างกัน | เปิดหน้าวิชา `CS261` จากรายการส่วนตัวตาม Story เดิม; เลือกเปิด G2 และ S1 จากกลุ่มวิชาเดียวกัน | หน้าวิชาเป็น `CS261`; G2 เปิดแนวข้อสอบ G2 ไม่ใช่ G1; S1 เปิด PDF ของ S1 ไม่ใช่ชิ้นอื่น; รายการแสดงผลงานทั้งสามแยกกันและข้อมูลปัจจุบันถูกต้อง; route/DTO ใหม่รอยืนยันใน Task94 |
| U10-TC03 รายการว่าง | ผู้ใช้ A Login และยังไม่มี bookmark; มี Course และผลงานของผู้ใช้อื่นในระบบ | เปิดรายการส่วนตัวและตรวจผล list API; กดทางไปหน้าค้นหารายวิชา | API ตอบ `200` พร้อมรายการว่าง; UI แสดงข้อความว่ารายการว่างและทางไปหน้าค้นหารายวิชา; ไม่แสดงข้อมูลของผู้อื่น; การนำทางไปหน้าค้นหารายวิชาทำงานได้ |
| U10-TC04 สิทธิ์แยกตามผู้ใช้และ Login | ผู้ใช้ A และ B มี token คนละชุด; A บันทึก G1; ทดสอบซ้ำโดยไม่มี/ใช้ token ผิด | B อ่าน list/state และนำ G1 ออก; เรียก API อีกครั้งโดยไม่มี token | B เห็นเฉพาะรายการของตนและเอา bookmark ของ A ออกไม่ได้; ไม่มี/ผิด token ตอบ `401`; ข้อมูลของ A ไม่เปลี่ยน |
| U10-TC05 รายการต้นทางไม่มีหรือ ID ผิด | ผู้ใช้ A Login; ใช้ G1 ที่ไม่มีอยู่ และ path ID `0`, ค่าติดลบ หรือไม่ใช่เลข | อ่าน state/เพิ่มรายการด้วย ID ดังกล่าว | G1 ที่ไม่มีอยู่: เพิ่มตอบ `404 GUIDE_NOT_FOUND`; ID ที่ไม่ถูกต้องตอบ `422`; ไม่มี bookmark ถูกสร้าง และ Course/Guide อื่นไม่เปลี่ยน |
| U10-TC06 ระบบจัดเก็บขัดข้อง | ผู้ใช้ A Login; มี G1; จำลองให้การอ่านหรือ commit ของ storage ล้มเหลว | เรียก list/state หรือเพิ่ม/นำออก แล้วตรวจ UI และสถานะซ้ำหลังระบบกลับมา | API ตอบ `503 SAVED_GUIDES_UNAVAILABLE`; UI แจ้งทำรายการไม่สำเร็จ ไม่แสดงผลสำเร็จลวง; transaction rollback และเมื่อกลับมาได้สถานะต้องตรงกับข้อมูลที่บันทึกจริง |
| U10-TC07 นำออกซ้ำและคงผลงาน | A และ B บันทึก G1; A บันทึก S1 ด้วย; G1 และ S1 อยู่ใน `CS261` | A นำ G1 ออกสองครั้ง แล้วตรวจรายการของ A/B, G1, S1, PDF และ Course | การนำออกซ้ำให้สถานะ `saved: false`; เฉพาะ bookmark G1 ของ A หายไป; G1, S1, PDF, Course และ bookmark ของ B ยังอยู่; รูปแบบ response สำหรับรายการสองชนิดรอยืนยันใน Task94 |

## API contract ที่อ้างอิง

Contract ปัจจุบันของ Guide bookmark คือ `SavedGuideState {id, saved}` และรายการเป็น `list[GuideDetailResponseDTO]` ตาม Router `/api/saved-guides` ส่วนสรุป PDF และการเปิดผลงานสองชนิดจากกลุ่มวิชาใน TC02 เป็นข้อกำหนดที่ต้องตกลง route/DTO กับ Task94 ก่อน implementation โดยอ้างแบบ Task104 ใน PR #106 ไม่ตีความว่า API ปัจจุบันรองรับสรุป PDF แล้ว

เอกสารอ้างอิงใน Repository:

- `backend/app/routers/saved_guides.py`
- `backend/app/services/saved_guides.py`
- `backend/app/models/saved_guide.py`
- `backend/test/test_saved_guides_api.py`
- `frontend/public/js/saved-courses.js`
- `frontend/public/js/guide-api.js`
- `docs/U5/design/task65-my-guides-api-spec.md` (ข้อกำหนดที่เกี่ยวกับ Guide และการคง Course)
